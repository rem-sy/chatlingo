# ChatLingo 设计方案

## 1. 用户与场景

**目标用户**：与 AI agent 高频对话的中日双语用户（开发者、知识工作者）。

**典型环境**：浏览器里的 ChatGPT/Claude 网页、桌面 agent 客户端、终端 CLI agent、IDE 内置对话。共同点：都是「输入框 + 输出区」形态，都接受剪贴板粘贴。

## 2. 交互形式（悬浮窗为核心）

### 2.1 主窗体：快捷输入条（Quick Bar）

```
┌─────────────────────────────────────────────┐
│ 把这个函数改成异步的，错误要打日志          │  ← 用户输入中文
│ ─────────────────────────────────────────── │
│ ▸ Convert this function to async, logging…  │  ← 流式英文译文
│                          [EN▾] [复制] [粘贴] │
└─────────────────────────────────────────────┘
```

- 全局快捷键 `Alt+T` 在**当前光标/鼠标位置附近**弹出；无边框、置顶、不抢宿主窗口逻辑焦点（输入完成后焦点自动归还）。
- 上半区输入原文，下半区流式渲染译文；`Enter` 确认翻译，`Esc` 关闭。
- 译文完成后默认「写入剪贴板 + 自动回填」：模拟 `Ctrl+V` 粘贴回原输入框（可关闭，改为仅复制）。
- 目标语言胶囊 `[EN▾]`：点击或 `Alt+1/2/3` 快切 EN/JA/原文直传。

### 2.2 副窗体：阅读面板（Reading Panel）

```
┌─ ChatLingo ────────────────── ◇ ─┐
│ ┌ 原文（agent 回复，英文）┐      │
│ │ The function now returns…│      │
│ └────────────────────────┘      │
│ ┌ 译文（中文，代码块保留）┐      │
│ │ 该函数现在返回…          │      │
│ │ ```rust                   │      │
│ │ async fn foo() {}         │      │
│ │ ```                       │      │
│ └────────────────────────┘      │
└──────────────────────────────────┘
```

- **剪贴板模式**：监听复制事件，检测到非中文（且非 ChatLingo 自己写入）的文本 → 自动翻译 → 角落滑入显示原文/译文对照。
- 面板可钉住成为常驻双语侧栏（跟随剪贴板滚动更新），也可设为被动模式（仅快捷键触发翻译当前剪贴板）。
- 防环：ChatLingo 写入剪贴板的内容带隐形标记（前缀零宽字符或独立记录 hash），监听器忽略。

### 2.3 托盘与设置

- 系统托盘常驻：开关剪贴板监听、暂停/恢复、设置、退出。
- 设置窗：引擎配置、方向语言、快捷键、回填行为、历史管理。

### 2.4 路线图形态（后续版本）

- 划词翻译弹窗（选中即译，参考 Glossy/pot）；
- OCR 截图翻译（参考 catwalk）。

## 3. 翻译流水线

```
捕获源                     路由                    引擎                     动作
────────                  ────────                ────────                 ────────
Quick Bar 提交  ──┐
                  ├─→ 语言检测 → 方向判定 → 格式分析 → [主引擎 → 备引擎] → 流式渲染
剪贴板监听      ──┤         │                                    │
                  │         │                                    ├→ 写剪贴板（带防环标记）
快捷键翻译当前   ──┘         │                                    ├→ 模拟粘贴回填
剪贴板内容                 └─ 已是目标语言/代码块占比过高 → 跳过翻译   └─→ 存入本地历史
```

### 3.1 语言检测

- 第一层（零成本）：脚本统计启发式——汉字占比、假名占比、拉丁字母占比 + 词形特征，覆盖 zh/en/ja 及「已是目标语言」的判断；
- 第二层（可选）：引擎返回的检测语言（DeepL/Google 自带）；
- 误判兜底：Quick Bar 界面显式显示「检测到：中文 → 英文」，一键纠正。

### 3.2 方向路由

| 触发方式 | 方向 | 目标语言 |
| --- | --- | --- |
| Quick Bar 提交 | 输入方向 | 用户配置（默认 EN，可切 JA） |
| 剪贴板/面板翻译 | 输出方向 | zh-CN |

### 3.3 格式保真策略

- 预处理：切分出代码块（``` 围栏）与行内代码（`` ` ``），LLM 提示词要求占位符原样保留，译后回填；
- LLM Prompt（输入方向示意）：
  > 你是专业翻译。将用户消息翻译为{目标语言}，供 AI 助手阅读。保留 Markdown 结构；`⟦CODE_i⟧` 占位符、URL、命令、API 名原样保留；语气自然、技术表述准确。只输出译文。
- 传统引擎兜底：仅对「无 Markdown 结构」的纯文本启用；含代码块的文本强制走 LLM。

### 3.4 引擎抽象

```rust
#[async_trait]
trait TranslationEngine {
    fn id(&self) -> &str;                      // "openai-compat" | "deepl" | ...
    async fn detect(&self, text: &str) -> Option<Lang>;
    async fn translate(&self, req: TranslateRequest) -> Result<TranslateStream>;
    fn capabilities(&self) -> Capabilities;    // streaming / markdown-safe / cost
}
```

- `TranslateStream`：LLM 走 SSE 流式；传统 API 一次性返回包装为单块流。
- 引擎链：`[primary, fallback...]`，失败/超时自动降级，托盘通知。
- 首发引擎：OpenAI 兼容（DeepSeek/OpenAI/Ollama，自定义 baseURL+model+key）→ DeepL → 后续按需（Google/微软/腾讯）。
- 缓存：原文 hash → 译文，LRU，会话级。

## 4. 技术架构

### 4.1 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Tauri 2 | 内存占用 ~40MB 级；pot/Glossy/hytrans 已验证该场景；Rust 侧做系统集成更稳 |
| 前端 | Vue 3 + TypeScript + Vite + UnoCSS | 轻量、响应式适合流式渲染 |
| Rust 关键 crate | `tauri-plugin-global-shortcut`、`tauri-plugin-clipboard-manager`、`keyring`（密钥）、`enigo`（模拟粘贴）、`sqlx`+SQLite（历史）、`reqwest`+`eventsource-stream`（SSE） | 均为 Tauri 生态成熟件 |

### 4.2 模块划分

```
chatlingo/
├── src/                        # Vue 前端
│   ├── windows/                # 每窗体一入口：quickbar / panel / settings
│   └── shared/                 # 流式渲染、Markdown 安全渲染（DOMPurify）
└── src-tauri/
    ├── main.rs                 # 多窗口装配、托盘
    ├── capture/                # 快捷键路由、剪贴板监听（防环）
    ├── pipeline/               # 语言检测、方向路由、格式切分/回填
    ├── engines/                # TranslationEngine trait + 各实现 + 降级链
    ├── actions/                # 写剪贴板、模拟粘贴、历史落库
    └── store/                  # 配置（keyring + JSON）、SQLite 历史
```

**数据流**：Rust 捕获事件 → pipeline 组装请求 → engine 流式产出 → Tauri event 逐块推给前端窗口渲染 → 完成后执行 actions。前端零业务逻辑，全部 Rust，便于未来换壳（如 CLI/侧边栏形态）。

### 4.3 配置模型（首版）

```jsonc
{
  "directions": { "inputTarget": "en", "outputTarget": "zh-CN", "quickSwitch": ["en", "ja"] },
  "engines": [
    { "id": "openai-compat", "baseURL": "https://api.deepseek.com/v1", "model": "deepseek-chat", "keyRef": "keyring://chatlingo/openai-compat" },
    { "id": "deepl", "keyRef": "keyring://chatlingo/deepl" }
  ],
  "quickbar": { "hotkey": "Alt+T", "autoPaste": true, "autoCopy": true },
  "clipboard": { "enabled": true, "minLength": 20, "ignoreApps": ["1password.exe"] },
  "history": { "enabled": true, "retentionDays": 30 }
}
```

### 4.4 风险与对策

| 风险 | 对策 |
| --- | --- |
| 模拟粘贴被目标应用拒绝/焦点丢失 | 回退为「仅复制 + 托盘提示」；按应用配置白名单 |
| 剪贴板监听误触发（复制密码等） | 最小长度阈值 + 忽略应用列表 + 语言检测不过则跳过 + 零成本启发式预筛 |
| LLM 译文破坏 Markdown | 占位符切分方案 + 流式渲染时校验围栏闭合，异常时展示原文并标记 |
| 快捷键冲突 | 设置页冲突检测，默认键位避开常用组合 |
| Windows/macOS 焦点行为差异 | 窗口 flag 分平台封装；以 Windows 为第一目标平台打磨 |

## 5. 首版范围（对应开发计划 M1）

**做**：Quick Bar（快捷键、流式译文、目标语言切换、复制/自动粘贴）、OpenAI 兼容引擎、语言检测与跳过、托盘常驻、基础设置。

**不做**：剪贴板自动翻译面板（M2）、DeepL（M3）、历史与缓存（M2-3）、划词/OCR（远期）。
