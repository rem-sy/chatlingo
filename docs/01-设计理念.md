# ChatLingo 设计理念

## 一句话

**ChatLingo 是一个住在屏幕角落的双向翻译管道：你说中文，它替你写英文/日文给 agent；agent 说英文，它替你读成中文。**

## 要解决的问题

与 AI agent（ChatGPT / Claude / DeepSeek / 编程 agent 等）对话时，语言选择是个两难：

1. **用中文问** → 模型理解与生成质量在英文语料下普遍更稳，尤其中长 prompt、代码注释、技术术语场景；
2. **用英文问** → 表达成本高，写出来的英文常常词不达意，反而降低沟通质量；
3. **英文回答** → 阅读速度远低于母语，长回复读得痛苦。

用户真正想要的不是「一个翻译器」，而是**幻觉般的体验：我用中文打字，agent 看到英文；agent 用英文回复，我看到中文**。中间的翻译步骤应该消失。

## 五条设计原则

### 1. 方向感知，而不是语言对

传统翻译器的心智模型是「源语言 → 目标语言」，每次都要选。ChatLingo 的心智模型是**「我说的话」和「agent 说的话」两个方向**：

- 我说的话（输入）→ 翻成英文（或日文，可切换）
- agent 说的话（输出）→ 翻成中文

方向由触发方式天然区分（快捷键呼出 = 我要说；复制 = 我要读），用户永远不需要思考语言对。

### 2. 无感优先

每一步交互成本都要审问：

- 呼出：一次全局快捷键，光标处直接出现输入条，不打断当前窗口焦点；
- 回填：译文出来后自动写回剪贴板并模拟粘贴（可选），按键次数为零；
- 阅读：复制的 agent 回复自动出译文悬浮预览。

**衡量标准：从「想到一句话」到「这句话以英文出现在输入框」≤ 2 次按键。**

### 3. 格式保真

Agent 的输出是 Markdown：代码块、表格、列表、行内代码。翻译必须：

- 代码块**原样跳过**（或仅译注释）；
- Markdown 结构完整保留；
- 行内代码、链接 URL、变量名不翻译。

这决定了 LLM 引擎优先——只有 LLM 能可靠做到；传统 API 仅作为纯文本兜底。

### 4. 本地优先，隐私默认

- API Key 存系统钥匙串（Windows Credential Manager / macOS Keychain），不落明文配置；
- 翻译历史存本地 SQLite，可一键清空；
- 无遥测、无账号、无云端依赖（除用户自己配置的翻译引擎 API）；
- 支持本地模型（Ollama / llama.cpp sidecar）实现全离线。

### 5. 可插拔一切

- **引擎可插拔**：LLM（任意 OpenAI 兼容端点）与传统 API（DeepL 等）统一抽象，可配置主备链路；
- **方向可插拔**：「输入目标语言」可随时切英文/日文/其他；
- **动作可插拔**：译文产出后干什么（复制/粘贴回填/仅显示）按场景配置。

## 非目标（明确不做）

- ❌ 网页内嵌双语渲染（沉浸式翻译的领地，需要浏览器插件形态）；
- ❌ OCR 截图翻译、语音翻译（后续大版本再评估）；
- ❌ 词典、例句、背单词等学习功能；
- ❌ 移动端。

## 成功画像

> 我在 DSH 里和一个编程 agent 结对。按 `Alt+T`，屏幕光标旁弹出一个输入条，我用中文写「把这个函数改成异步的，错误要打日志」，按下回车。输入条里流式出现英文译文，同时译文已进入剪贴板，`Ctrl+V` 贴进 agent 对话框。agent 回复了一大段英文方案，我全选复制——屏幕角落的悬浮面板立刻叠出中文译文，代码块原封未动。
>
> 全程我没有打开过任何翻译软件。
